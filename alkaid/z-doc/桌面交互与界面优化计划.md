# 瑶光台桌面交互与界面优化计划

更新日期为 2026-11-04。本计划基于最新桌面与宿主代码，以及用户反馈制定，优先改善操作流程、入口组织、反馈、弹窗和动效。

视觉基准沿用当前奶油色、柔和渐变、毛玻璃、圆角、字体与绿色强调色。布局和操作流程围绕桌面使用习惯重新梳理。

## 1 当前依据与验证范围

本轮重新读取了 `desktop/index.html`、`desktop/1.css`、`desktop/runtime.css`、`desktop/src/main.js`、`desktop/src/packages.js`、宿主打包逻辑及最新开发进度。已有平台设置、权限调整、数据清理、本地发布者、备份恢复和操作记录等功能纳入优化范围。

初版计划来自代码审查。本轮已通过项目的 CEF 调试端口取得真实截图，并执行 Windows 原生窗口与系统选择器测试。下表保留改动前的问题依据，实施结果见第 9 节。

| 代码可确认的现状 | 优化任务 |
|---|---|
| 应用管理标题栏集中插件管理、打包、安装和刷新 | 分开日常使用、管理和开发入口 |
| 关于同时出现在菜单、桌面和 Dock，启动时自动打开应用管理 | 重新定义默认桌面及固定入口 |
| 应用行排列详情、打开或切换、关闭、恢复和卸载 | 突出主要操作，其他操作进入详情与更多菜单 |
| 打包由 preparePack 一次调用递归打开目录、可选私钥、保存选择器 | 将输入、输出选择与实际生成分成用户可控制的步骤 |
| 输出默认名为 application.ypkg，完成状态主要为一段文字 | 自动命名并提供输出结果和后续动作 |
| 模板切换使用 window.confirm，其他操作使用各类 dialog | 统一确认组件、焦点、按钮和取消语义 |
| 打包工作台使用局部背景、文字色和独立控件样式 | 汇总到当前设计令牌，统一表单细节 |
| 详情、操作记录、清理等使用多层弹窗 | 长内容进入页面或详情面板，短确认使用弹窗 |
| 插件面板没有对应 Dock 项，关闭处理直接访问该 Dock 元素 | 修复入口与窗口映射，避免关闭流程异常 |

## 2 优化目标

- 用户能找到应用、安装入口、设置和打包工具。
- 每次文件选择前明确说明选择对象、用途及下一步。
- 操作可预期，返回、取消或出错后保留已填写内容。
- 所有业务弹窗、菜单、表单、通知使用一致的视觉和行为。
- 运行中、等待中、失败和完成都有对应状态，状态以宿主结果为依据。
- 交互支持鼠标和键盘，动画尊重减少动态效果设置。

## 3 入口和桌面布局

| 区域 | 建议职责 |
|---|---|
| 顶部品牌菜单 | 关于、帮助、退出 |
| 顶部应用入口 | 应用库、安装应用、运行中应用 |
| 顶部工具入口 | 打包工作台、插件管理、诊断 |
| 顶部设置入口 | 外观、时钟、数据与平台设置 |
| 顶部状态区 | 时钟和任务状态，失败可进入任务详情 |
| 桌面 | 应用快捷入口，选中、双击打开、右键操作 |
| Dock | 应用库、固定应用和运行中的应用，清晰区分活动状态 |
| 应用库 | 搜索、运行状态筛选、安装入口和应用列表 |

默认启动呈现桌面，首次使用提供明确的安装入口，后续可恢复上次工作区。关于、诊断、发布者备份等低频功能按场景归入菜单或工具页。

应用行保留“打开”或“切换”作为主要动作，“更多”提供详情、关闭、版本恢复和卸载。危险操作进入明确确认步骤。插件管理展示被哪些应用依赖及当前使用状态。

## 4 打包工作台流程

工作台作为独立工具面板，提供可见步骤、上一步、下一步和草稿状态。

### 步骤一 选择项目

明确显示“选择前端构建目录”，解释需要包含入口 HTML 和静态资源。用户点击后打开系统目录选择器，返回工作台展示目录、入口检查与资源摘要。操作采用“选择本地目录”的表述。

### 步骤二 应用信息

填写名称、标识、版本、入口和权限。字段旁提供示例、校验及简短用途说明。高级选项渐进展开，普通与高级模式切换保留草稿，冲突或覆盖先明确说明。

### 步骤三 发布者

已有发布者显示名称和简短身份信息，完整指纹可展开或复制。首次使用提供创建与恢复入口。私钥选择作为明确的高级操作，备份恢复独立成流程。

### 步骤四 输出与确认

在工作台显示建议文件名，例如 `my-app-1.0.0.ypkg`，以及“生成的安装包将保存到这里”的说明。用户主动点击“选择保存位置”后才打开保存选择器，选择后回到工作台展示目标。

用户核对项目、版本、发布者、权限和输出位置后，点击“开始打包”。取消保存选择器返回当前步骤，保留项目和表单。

### 步骤五 生成与结果

按后端实际支持显示检查、生成、签名、验证阶段。缺少可量测进度时显示阶段与等待状态。失败给出原因、修复入口和重试，保留输入。

成功页显示文件名、版本、保存位置和验证结果，提供“打开所在文件夹”“安装此包”“继续打包”。这些动作依赖宿主提供绑定本次结果的受控接口。

### 必要接线调整

宿主将目前的递归选择流程拆成选择项目、选择输出和执行打包，SDK 返回受控任务或选择凭据。真实路径和写入授权由宿主管理。用户修改项目或输出后，旧凭据应失效或重新验证。

关闭工作台与取消后台任务分别定义。任务运行时允许返回桌面并从任务入口查看进度，关闭面板时明确任务的后续状态。取消、覆盖、目标变化和失败清理均需真实验证。

## 5 弹窗与表单体系

| 场景 | 展示方式和行为 |
|---|---|
| 打包、设置、诊断 | 长流程使用工具面板，保留导航和上下文 |
| 应用详情、权限、依赖和数据 | 详情区域分组展示，避免反复堆叠模态框 |
| 安装或更新 | 信息确认、执行状态和完成结果连续呈现 |
| 卸载、删除数据、恢复版本 | 短确认弹窗，显示对象、影响范围和明确动词 |
| 发布者创建、备份和恢复 | 独立表单流程，说明文件和口令用途 |
| 普通成功反馈 | 轻提示和对象状态更新 |
| 需要处理的失败 | 就地错误与可再次打开的任务详情 |
| 系统文件及目录选择 | 保留系统选择器，前后由产品页面说明用途和结果 |

统一按钮、输入框、选择框、复选框、开关、标签、菜单、滚动区域和弹窗遮罩。优先保留标准控件语义，再用现有设计令牌完善样式。

弹窗统一标题、说明、内容、错误区和操作区。键盘焦点进入正确控件，Tab 在模态范围内移动，关闭后回到触发入口。Esc、遮罩点击及关闭按钮按同一规则处理，未保存内容与不可取消的执行阶段单独说明。危险操作默认聚焦安全选项。

替换当前模板切换的浏览器确认框。原生文件选择器按 Windows 行为使用，产品内确认和表单采用瑶光台组件。

## 6 交互和动效

- 桌面单击选中、双击打开，Enter 打开，右键和更多菜单提供等价入口。
- 拖动、窗口激活、关闭、恢复和 Dock 状态建立一致行为，覆盖没有固定 Dock 项的面板。
- 表单校验紧邻字段，提交失败保留输入，处理中防止重复提交。
- 列表更新保留焦点、滚动位置和当前选择，任务反馈可从状态入口重新查看。
- 统一悬停、按下、禁用、选中、加载、成功和错误状态。
- 微反馈建议 120—160 毫秒，菜单和弹窗建议 160—220 毫秒，窗口切换建议 200—260 毫秒，实际参数以 CEF 验收为准。
- 动画主要改变透明度和变换属性，关闭动画结束后再隐藏节点，快速反复操作正确处理动画中断。
- 尊重 `prefers-reduced-motion`，保留清晰的静态反馈。持续运行状态使用稳定标记，加载动画只用于真实进行中的操作。

## 7 实施顺序

| 阶段 | 交付内容 | 验收条件 |
|---|---|---|
| U0 当前体验基线 | 真实 CEF 截图、操作录屏、入口与弹窗清单、视觉令牌 | 每个核心流程有当前画面和可复现步骤 |
| U1 打包流程 | 分步工作台、输入与输出独立选择、结果页、必要宿主接线 | 首次用户能解释所选目录与保存位置，取消返回不丢内容 |
| U2 公共组件 | 表单、按钮、弹窗、菜单、提示及焦点规则 | 业务确认样式一致，鼠标和键盘均可完成 |
| U3 导航与窗口 | 桌面、应用库、工具、设置、Dock 与详情布局 | 高频入口易找到，面板打开关闭无异常，危险动作位置明确 |
| U4 状态与动效 | 执行反馈、错误恢复、窗口过渡和减少动态效果 | 动画与实际状态一致，连续点击和任务中断可恢复 |
| U5 整体验收 | 全页面和原生选择器往返验证，样式对照与回归记录 | 新用户完成打包安装，全流程保持现有视觉设计语言 |

U1 与 U2 优先，先让打包流程成为可体验样例，再将公共规则推广到其他页面。现有模块由 `desktop/src/main.js` 与 `desktop/src/packages.js` 逐步拆分为必要的面板、弹窗和任务组件，减少跨页面共享状态。

## 8 验收场景

1. 首次启动，找到安装和打包入口。
2. 首次创建发布者，选择项目、填写信息、明确选择输出并生成包。
3. 在每个选择步骤取消、返回或修改，已填写数据仍可继续使用。
4. 输入无效版本、缺失入口、签名失败、输出被占用时，定位问题并重试。
5. 打包成功后找到文件并安装，重复打包时保留合理默认值。
6. 应用打开、切换、关闭、详情、授权、恢复、卸载及两类数据清理。
7. 插件安装、依赖阻止卸载、面板关闭和任务失败恢复。
8. 发布者备份、错误口令、恢复以及诊断记录查看。
9. 纯键盘操作、Esc、焦点恢复、缩小窗口、高 DPI 和减少动态效果。
10. 多面板、长名称、空列表、任务执行中关闭面板、连续快速点击。

每轮同时检查默认暖白主题及已有其他配色，输出改前改后截图、实际功能回归结果和未通过项。真实 CEF 及系统文件选择器是打包流程最终验收环境。


## 9 2026-11-04 首轮实施结果

本轮保持暖白、松绿、渐变和毛玻璃视觉，并交付以下可运行改动：

- 主桌面改为无原生标题栏窗口，顶部自绘区提供最小化、最大化／还原和退出确认；空白区域用于拖动。普通应用窗口继续使用各自现有窗口生命周期。
- 新图标采用松绿与暖白的星光、地平线形象。PNG、16–256 像素 ICO、启动程序资源、任务栏／Alt-Tab 图标与 Windows 通知区图标均已接入。托盘双击显示桌面，右键提供显示与退出。
- 默认启动展示桌面，应用、工具、设置分开；关于归入品牌菜单。工具页集中打包、插件、诊断，顶部任务入口可查看进度与结果。
- 应用库支持名称／标识搜索、运行状态筛选；应用行保留打开／切换，其余动作归入更多菜单。桌面图标支持单击选中、双击／Enter 打开与右键查看详情。
- 打包采用「应用信息与发布者 → 选择构建目录 → 确认保存位置 → 生成安装包」。完成目录选择后停在说明页，由用户主动选择输出；输出选择后仍需点击生成。取消选择返回当前步骤，返回编辑释放待处理任务并保留表单。
- 输出文件默认名由应用标识和版本组成；结果页显示保存位置并提供打开所在文件夹、安装此包。安装入口重新走验签和信任确认。
- 新增 `awaitingInput` 任务状态及 `apps.advancePack/cancelPack/revealPack/installPacked`。`preparePack` 的可选 `interactive` 参数默认关闭，旧调用保持原流程。新增方法及窗口控制仅对受信桌面管理权限开放。
- 新增公共交互模块和样式层，替换模板切换的浏览器确认框，统一表单、按钮、菜单、业务弹窗、焦点样式和动效；支持减少动态效果。修复无 Dock 对应项的插件面板关闭异常。

### 本轮验证

- Windows x64 Release 编译与契约生成一致性通过。
- CTest 4/4；SDK 32 项、桌面桥接 2 项通过。文件硬链接测试在真实 Windows 环境通过，未修改其权限断言。
- 真实 CEF 宿主 10 项、应用生命周期与隔离 14 项通过。
- 新桌面体验测试 7 组通过，覆盖无原生标题栏、拖动命中区、任务栏图标句柄、最小化、最大化、托盘双击恢复、搜索、入口开关、模板 Esc 取消、退出取消与减少动态效果。
- 分步打包验证目录选择后的停顿、保存选择取消、明确点击生成、任务入口恢复、输出验签、生成结果转安装确认；发布者加密备份、重启同指纹打包、错误备份口令拒绝以及空白环境恢复后同指纹打包通过。

### 后续完善范围

本轮覆盖 U1–U4 的主要路径及 U5 的针对性回归，不代表原计划所有扩展项均完成。项目资源摘要与入口预检查、跨重启打包草稿、插件反向依赖展示、长详情面板化、完整逐字段校验仍可继续完善。实际压缩任务当前只提供真实阶段信息，不提供虚构百分比，也没有中途强制终止按钮。

当前实际验收环境为 Windows 的 150% 缩放。多显示器、其他 DPI、完整键盘遍历与所有主题组合仍需扩大人工验收；原生文件／目录选择器保留 Windows 标准行为。


## 10 设置页与 Dock 细化

用户截图指出设置页比例松散、原生下拉展开样式突兀，Dock 的 emoji、文字图标与品牌图标缺少一致性。本轮收紧设置页尺寸，加入桌面配色缩略预览，将时间格式改为分段选择、秒数改为开关，并统一 Dock 图标、间距、状态点和悬停提示。继续使用现有暖白、松绿及毛玻璃视觉，保留原配置字段与显式保存行为。

前端构建和真实 CEF 设置保存、重启恢复、默认值恢复通过；方向键选择、空格开关、Dock 入口及运行图标已验证。证据：`build/ui-polish-verification/settings.png`、`desktop.png`、`dock-running.png`。
