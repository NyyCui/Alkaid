# 瑶光台项目规划与开发计划 v3

更新日期为 2026-11-04。本版根据最新项目目标制定，作为后续开发的规划入口。规划版本号与 YPKG 格式版本、运行时版本分别管理。

本轮以五项核心能力为主线，包括应用包与应用管理、JS/C++ 通信、插件化系统能力、单应用单窗口、系统配置。各阶段完成状态记录在 [重构开发进度](重构开发进度.md)。

## 1 项目定位与目标

瑶光台是 Windows 上的前端应用运行平台。开发者提供前端构建目录，填写应用名称、发布者、版本等信息，通过打包工具生成 `.ypkg`。用户安装后打开应用，应用通过统一 JS SDK 使用文件、网络和硬件设备等能力。

前端负责界面、交互和业务编排。平台负责应用身份、安装、通信、系统能力、插件、窗口及持久化配置。

| 使用者 | 主要工作 |
|---|---|
| 应用开发者 | 开发前端、声明能力和插件依赖、构建应用包、发布更新 |
| 插件开发者 | 实现系统或硬件能力、注册接口、构建插件包、维护兼容版本 |
| 平台使用者 | 安装应用和插件、授权、运行、配置、更新和卸载 |

首个完整版本必须贯通以下流程。

前端项目 → 打包 → 安装 → 打开唯一窗口 → 调用系统能力或硬件插件 → 保存配置 → 更新 → 卸载。

前端运行目标是支持构建后的 HTML/CSS/JS 资源，覆盖普通静态页面和主流框架构建产物。纯页面可以直接加载，调用系统能力时接入 SDK。依赖服务端渲染的项目需要静态导出或配套后端服务。

## 2 已明确范围与规划默认选择

以全新开发基线交付。包、SDK/RPC、插件、窗口和持久化均可重新实现。使用独立数据目录全新初始化，所有包验收用例均从当前源码生成。现有源码可按新契约选用。

### 2.1 本轮必达范围

- 完善自定义 YPKG 应用交付规范和目录打包流程。
- 应用安装、运行、更新、恢复和卸载。
- 统一 JS/C++ 通信及可扩展系统调用。
- 插件化提供系统和硬件能力，包含独立插件管理与真实设备验证。
- 每个应用一个主窗口，重复打开聚焦已有窗口。
- 使用 SQLite 管理持久化配置，提供统一配置服务。

### 2.2 规划采用的默认选择

以下为实现建议，在 M1 契约阶段记录最终决策。

| 决策 | 规划默认 | 定稿要求 |
|---|---|---|
| 技术基线 | 继续使用当前 C++20、CEF、Windows x64 和 SQLite | 锁定依赖，确定支持的 Windows 版本与环境 |
| YPKG 容器 | ZIP 容器、新清单、完整性列表和签名 | 确定新清单及签名规则 |
| 原生插件运行 | 由独立工作进程承载，使用版本化协议 | 分别定义故障隔离、权限约束、插件信任和升级规则 |
| 首个硬件样例 | 优先考虑串口 | 确定实际设备型号、协议、驱动前提和验收步骤 |
| 配置存储 | SQLite 配合系统保护的凭据存储 | 确定作用域、迁移版本、备份和恢复策略 |

当前 `.ypkg` 后缀继续作为应用交付入口。插件包的容器复用、类型标识和扩展名在 M1 一起确定。

后续版本根据真实需求扩展更多设备插件、插件分发、平台自动更新、媒体资源支持和跨平台能力。

## 4 核心架构与职责

| 层次 | 职责 |
|---|---|
| 前端应用及平台桌面 | 页面、交互、业务编排和管理界面 |
| JS SDK | 类型化调用、错误转换、取消、分块和事件订阅 |
| CEF 通信适配 | 页面上下文、IPC、导航和销毁通知 |
| 宿主调用网关 | 实际调用身份、契约、授权、配额和调度 |
| 能力注册与插件管理 | 方法及事件注册、依赖、版本绑定、初始化和释放 |
| 系统服务及原生插件 | 文件、存储、网络、设备和系统适配 |
| 持久化层 | 应用、插件、版本、授权、配置和操作记录 |

新增能力通过注册接口接入，共用调用上下文、错误、事件和资源回收规则。应用管理、授权管理等平台接口保留管理身份要求。插件方法命名空间需要防止覆盖平台接口或其他插件。

配置、应用注册表和插件注册表的写入、迁移及恢复规则由宿主统一协调。设备和文件操作放入有上限的工作队列，窗口线程保持响应。

## 5 YPKG 包格式与应用管理

### 5.1 包清单

| 信息组 | 内容 |
|---|---|
| 格式 | 包格式版本、包类型和清单版本 |
| 应用身份 | 唯一应用 ID、名称、版本、说明和图标 |
| 发布者 | 展示名称、签名公钥标识和可选联系方式 |
| 运行条件 | 最低平台版本、SDK/API 兼容版本 |
| 前端入口 | 启动页面、路由模式和资源策略 |
| 窗口 | 标题、默认尺寸、最小尺寸和是否可调整 |
| 能力 | 文件、网络、设备等权限及范围 |
| 插件依赖 | 插件 ID、版本范围、必需或可选 |
| 完整性 | 资源列表、大小、摘要和签名 |

M1 分别提供普通应用、依赖插件的应用、原生插件三种完整清单样例。清单扩展同步更新打包器、校验器、安装预览和运行时读取逻辑。

发布者名称作为签名自述信息展示，签名密钥用于验证来源和应用归属。信任策略定义完整指纹查看、撤销、密钥轮换及丢钥后的处理流程。

### 5.2 格式演进与资源加载

- 区分包格式版本、应用版本、运行时 API 版本和插件协议版本。
- 定义必需字段、可选字段、未知字段以及未知能力的处理规则。
- 仅使用当前格式生成的包验证清单、签名及安装流程。
- 校验完整性、路径、重复条目、压缩比、资源数量和容量。
- 确定按需加载和缓存策略，验证大资源读取、Range、取消及版本切换。
- 分别设置包容量、单资源容量、预加载预算、私有数据和传输配额。

### 5.3 打包工具

命令行提供项目初始化、开发预览、构建包、检查包和查看包信息。可视化工具提供选择前端目录、填写元数据、窗口参数、权限、插件依赖、签名身份和输出位置的流程。

两种入口共用校验规则，支持保存与重新打开项目配置。打包前检查入口、资源路径、清单、依赖和容量，错误定位到具体字段或文件。发布者私钥独立保存在开发侧。

### 5.4 安装与版本管理

- 安装预览、来源确认、权限确认和插件依赖检查。
- 必需依赖缺失时明确阻止启动，可选依赖缺失时可查询能力并降级。
- 新版本写入独立位置，确认完成后激活，运行实例绑定固定资源版本。
- 更新和恢复前协调关窗、任务结束以及插件设备资源释放。
- 恢复上一版本时核对授权范围和数据兼容性。
- 卸载时选择保留或删除数据，并明确缓存、配置和业务数据的清理范围。
- 安装中断、文件占用、包损坏和数据库迁移失败后可恢复。
- 操作记录、实际激活版本和用户界面状态保持一致。

### 5.5 前端兼容验收

使用静态页面、Vue 和 React 实际构建产物验收入口、资源路径、路由刷新、动态导入及字体。Worker、WASM、媒体等能力形成支持清单，逐项验证后开放。应用需要远程资源或接口时，按平台网络契约接入。

## 6 JS 与 C++ 通信

- 使用稳定的方法名和命名空间，通过共享契约描述参数、结果、错误、权限、超时和版本。
- 提供异步请求、取消、进度、事件订阅及取消订阅。
- 支持大数据分块、背压、并发限制和资源配额。
- 应用刷新、关窗、权限撤销和插件退出后回收请求与订阅。
- 提供能力查询，明确反馈插件缺失、版本不兼容和能力不可用。
- 副作用操作明确重复请求、结果查询和重试规则，写操作超时后通过实际状态判定结果。
- 事件包含范围和序号，高频事件合并并限定队列，丢失或重连后可读取状态快照。
- 参数和返回值校验逐步从契约生成，SDK 和宿主共用版本来源。

验收覆盖非法参数、伪造身份、越权、重复请求、超时、取消、乱序和迟到响应。文件与网络 SDK 及三个样例统一按新接口验收。

## 7 插件化系统能力

### 7.1 能力模块与原生扩展

平台内置的文件、存储、网络模块通过统一接口注册。可独立安装的原生插件用于串口、USB/HID、打印及厂商设备 SDK 等能力。

插件声明身份、版本、签名、兼容范围、能力、依赖和配置 schema。应用声明依赖范围，激活时锁定实际版本，运行期间保持绑定。

模块注册需要检查名称冲突和依赖环，初始化失败时清理已分配资源，按依赖逆序停止。模块注册实现以本轮契约为准。

### 7.2 插件管理与运行

- 提供安装、启用、停用、更新、卸载及失败恢复。
- 更新或卸载前展示依赖应用，受影响应用完成关闭和资源释放。
- 受依赖插件的卸载应阻止执行，或在用户明确确认后停用相关应用。
- 工作进程执行启动握手、健康检查、调用、取消和退出协议。
- 插件版本和工作进程协议独立演进，明确消息格式、内存所有权和错误语义。
- 插件崩溃后回收资源，通知应用，并提供受控重启。
- 回滚插件时核对配置兼容性，避免旧版本误读新配置。

原生插件由独立工作进程承载是本规划的默认建议。普通用户权限的独立进程提供故障隔离，操作系统权限约束需要另外设计与验收。M1 明确可信插件与其他插件的运行策略，以及访问系统资源所需的实际权限。

### 7.3 硬件接口

统一设计枚举、选择、连接、读写、状态查询、事件订阅、取消和释放。

设备句柄绑定应用及会话，定义独占与共享、热拔插、重连、超时、半完成写入、应用关闭和插件崩溃后的处理。插件所需驱动、厂商运行库和系统权限写入兼容要求。

首期优先考虑串口样例，实际设备型号和协议在 M1 确定。缺少设备时可以先开发契约和软件测试，硬件阶段完成以真机记录为依据。

## 8 单应用单窗口

应用 ID 对应一个运行实例和一个主窗口。状态覆盖启动中、运行中、关闭中、已停止和崩溃。

- 连续启动只创建一个窗口，再次打开恢复并聚焦已有窗口。
- 区分启动请求受理与页面实际就绪，启动失败能重试并显示原因。
- 从包清单读取默认尺寸、最小尺寸和窗口属性。
- 保存位置、尺寸和最大化状态，显示器变化后恢复到可见区域。
- 关闭前处理应用保存、插件任务及设备资源。
- 应用拒绝关闭时恢复交互，清理本次关闭协商状态。
- 无响应和崩溃时提供恢复或结束入口。
- 平台退出协调全部应用，明确等待、取消退出与强制结束行为。

验收包含快速连续打开、启动中重复打开、保存取消、多应用退出、设备阻塞、桌面崩溃及多屏变化。

## 9 系统配置与持久化

| 配置范围 | 示例 |
|---|---|
| 平台 | 主题、日志级别、更新偏好和数据目录相关设置 |
| 应用 | 窗口状态、用户偏好和能力授权 |
| 插件 | 启用状态、连接参数和运行配置 |
| 应用私有数据 | 业务设置、草稿及其他应用数据 |

配置服务定义类型、默认值、校验、作用域和写权限，支持事务更新、版本迁移、变更通知、备份及恢复。凭据采用系统保护存储，数据库记录引用及必要元信息。

更新、回退、卸载和重装分别定义配置保留与迁移行为。数据库备份需要包含一致的 SQLite 状态，恢复前检查版本和归属。迁移失败时保留可恢复副本，并提供明确的修复入口。

验收覆盖重启恢复、并发修改、迁移中断、插件回滚、卸载重装以及跨作用域访问拒绝。

## 10 开发阶段与完成标准

M0 至 M8 是新版路线的里程碑编号，已有批次继续作为历史验收记录。

| 阶段 | 主要任务 | 完成标准 |
|---|---|---|
| M0 当前代码基线 | 版本管理、产物与测试清点、标记网络未完成项、统一构建入口 | 当前状态可重现、可追踪、可回退 |
| M1 核心契约定稿 | YPKG、插件、RPC、窗口、配置契约与全新数据初始化规则 | 字段定义、状态流程、格式版本门槛和验收用例齐全 |
| M2 包与应用交付 | 清单、CLI、可视化打包、依赖检查、安装更新卸载恢复 | 普通前端目录生成包并完成安装更新 |
| M3 通信与模块接入 | 能力注册、事件、插件调用入口和配置基础服务 | 新增模块通过注册接入，现有 SDK 回归通过 |
| M4 插件运行体系 | 插件注册表、工作进程、版本绑定、健康检查和生命周期 | 独立插件可运行，缺失、崩溃和升级失败可恢复 |

| M6 窗口与管理界面 | 窗口配置、应用详情、权限、插件管理、设置和数据清理 | 五大核心能力都有完整用户操作入口 |
| M7 联调与恢复加固 | 新数据目录初始化、故障注入、容量、多应用和兼容测试 | 安装中断、更新失败、设备断开、异常退出均有验证结果 |
| M8 首个正式交付 | 平台安装程序、示例、开发文档和干净环境验收 | 新机器可安装平台并完成应用及插件使用流程 |

依赖顺序为 M0 → M1 → M2/M3 → M4 → M5/M6 → M7 → M8。

M2 和 M3 可以并行。管理界面基础工作可提前开展，具体联调等待对应服务。网络已有实现的缺口纳入 M0 清点，并在 M3、M5 接入统一机制时完成收尾。

| 包与安装 | 损坏包、签名错误、依赖缺失、版本不兼容、安装中断 |

| 通信 | 非法参数、重复请求、超时、取消、迟到响应、事件清理 |
| 权限 | 应用隔离、撤销、插件能力范围、更新后权限变化 |
| 设备 | 连接失败、竞争占用、热拔插、超时、插件崩溃 |
| 窗口 | 重复启动、保存取消、无响应、平台退出、多屏恢复 |
| 数据 | 更新保留、卸载删除、迁移失败、备份恢复、回退兼容 |
| Windows | 支持的 Win10/11 环境、中文路径、高 DPI、文件占用、低磁盘 |
| 性能 | 冷热启动、空闲占用、多应用运行、大包和大文件操作 |

每阶段交付可运行产物、版本及哈希、测试结果和已知限制。软件测试与真实设备结果分别记录，硬件完成条件包含真机验证。

包解析增加恶意输入及模糊测试，安装和迁移增加持久化阶段故障注入。性能基线记录测试机器、系统、CEF 版本、应用数量和资源大小，再设定可量测预算。

## 12 工作量与协作方式

基于当前已有代码，初步估算为 50—80 人日，包含实现、联调、测试和文档。估算前提是首期接入一种硬件、文件与存储按新契约实现。M1 完成后重新估算，实际日历周期取决于人员投入、依赖等待和设备条件。

| 工作方向 | 责任范围 |
|---|---|
| 宿主与通信 | RPC、能力注册、窗口、插件进程和配置 |
| 包与应用管理 | YPKG、打包工具、安装更新、故障恢复 |
| SDK、界面与验证 | 开发者接口、管理界面、样例和端到端测试 |

每批记录目标、改动、产物、测试结果、已知问题和下一步。阶段通过后建立版本标签。版本管理排除签名私钥、构建产物和测试运行数据。

关键依赖包括清单与插件协议定稿、真实设备与驱动环境、目标 Windows 测试环境。影响范围或工作量的变更先更新本计划的阶段与验收条件，再进入开发。
