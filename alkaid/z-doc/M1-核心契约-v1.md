# M1 核心契约 v1

本文件定义全新开发基线。包格式、SDK、宿主、插件、配置和示例均可重新实现。开发版产物只用于历史核对。

## 包与数据基线

沿用 ZIP 容器和现有签名校验流程。下一版清单使用 `manifestVersion: 3` 和 `type: "app" | "plugin"`。应用和插件统一使用 `.ypkg`，安装器在验签后按清单类型分发。容器格式、清单、应用版本、SDK API 与插件协议分别演进。

- 宿主只识别 manifestVersion 3。样例从源码按新清单打包并签名。包验收全部使用当前格式生成的样例和故障夹具。
- 新版使用独立数据根目录，首次启动新建注册表、授权、CEF profile、应用数据和配置库。原开发目录留存，用户数据清理通过独立操作处理。
- 更新先校验签名、运行条件和依赖，再暂存并切换版本。失败保留原活动版本。回滚按当前授权上限重新计算有效权限。

以下为三种开发侧清单样例，发布密钥标识由打包器补入。

```json
{"manifestVersion":3,"type":"app","appId":"com.example.notes","name":"便签","version":"1.2.0","publisher":{"name":"示例发布者"},"runtime":{"apiMajor":1,"minVersion":"2.0.0"},"entry":"index.html","routing":"hash","instanceMode":"single","window":{"width":800,"height":600,"minWidth":480,"minHeight":320,"resizable":true},"permissions":["storage.kv"],"dependencies":[]}
```

```json
{"manifestVersion":3,"type":"app","appId":"com.example.device","name":"设备控制","version":"1.0.0","publisher":{"name":"示例发布者"},"runtime":{"apiMajor":1,"minVersion":"2.0.0"},"entry":"index.html","routing":"hash","instanceMode":"single","window":{"width":900,"height":620,"minWidth":540,"minHeight":360,"resizable":true},"permissions":["plugin.com.example.serial"],"dependencies":[{"pluginId":"com.example.serial","minVersion":"1.0.0","maxVersionExclusive":"2.0.0","required":true}]}
```

```json
{"manifestVersion":3,"type":"plugin","pluginId":"com.example.serial","name":"串口","version":"1.0.0","publisher":{"name":"示例发布者"},"protocolMajor":1,"architecture":"win-x64","entry":"worker.exe","capabilities":["open","read","write","close"],"events":["disconnected"]}
```

## 插件与设备生命周期

- 宿主完成信任和依赖解析后，由独立工作进程承载已验证插件。握手校验协议主版本和方法、事件目录。应用仅能调用声明并获准的插件方法。方法和事件使用插件 ID 命名空间，系统方法保留独立命名空间。
- 每次调用带请求 ID 和截止时间，宿主绑定应用身份、会话、插件实例及版本。取消和超时后丢弃迟到响应。写入超时不得自动重试。应用会话撤销后停止投递事件。
- 设备句柄由宿主分配并绑定会话和插件实例，插件内部句柄留在工作进程。应用关闭、授权撤销、插件退出、设备拔出时回收句柄。插件崩溃后原句柄失效，由应用重新请求打开设备。
- 升级时已有会话继续使用绑定版本，新会话使用新活动版本。新版启动或握手失败时保留旧活动版本。退出先协商释放资源，再按期限终止未响应工作进程。进程权限、IPC 端点 ACL、签名信任和资源上限须纳入安全验收。

## 清单字段约束

- v3 所有字段按对应样例校验，拒绝未知字段、重复键及类型不符。发行清单另需顶层 `publisherKeyId`。仅声明 `net.request` 的应用可附带 `networkEndpoints`，每个端点声明唯一 ID、基础 URL、允许的方法及私网访问开关，授权绑定实际端点范围。
- 签名输入由域前缀、4 字节小端清单长度、原始清单字节、4 字节小端完整性清单长度、原始完整性清单字节依序拼接。域前缀为 `YPKG-V3\n`。使用 ECDSA P-256 和 SHA-256 验签。
- ID 为小写点分段标识，版本为 major.minor.patch，路径禁止绝对路径、上级跳转、链接及大小写冲突。初始限额为包 32 MiB、展开后 32 MiB、单资源 8 MiB、最多 512 个资源。应用资源放在 `assets/`，应用入口必须是清单内实际存在的 HTML。首版路由仅支持 `hash`。插件入口固定为签名覆盖的 `assets/worker.exe`，仅插件清单允许该入口。普通应用不得携带可执行文件。
- `publisher.name`、`name` 为非空文本，最大 128 个 UTF-8 字节。窗口宽高为 1 至 8192 的整数，最小尺寸不得超过默认尺寸。应用固定 `instanceMode: "single"`。
- 每个应用最多声明 16 个依赖，按 `pluginId` 去重，版本范围为下限含、上限不含。必需依赖缺失时拒绝激活和启动，已安装应用保留其数据。可选依赖不可用时，相关方法返回 `PLUGIN_UNAVAILABLE`。候选版本须来自已授权的发布者，取满足范围的最高可用版本。
- `plugin.<pluginId>` 权限只能用于清单中声明的依赖。授予插件能力须经应用安装授权和插件发布者信任两项检查。撤销任一项后关闭该应用的对应插件会话。
- 插件要求 `architecture: "win-x64"`、`protocolMajor: 1`。方法和事件名为 1 至 64 字符的 ASCII 标识符，首字符为小写字母，其余为 ASCII 字母、数字或下划线。每个列表最多 128 项，拒绝重复。

## 插件 IPC v1

宿主与工作进程使用专用本机管道，消息以 4 字节小端长度加 UTF-8 JSON 编码，单帧上限 256 KiB。管道限制到当前用户和宿主启动的进程，宿主验证实际连接 PID。每个插件实例最多 16 个在途请求，等待队列最多 64 个，超限返回 `RESOURCE_EXHAUSTED`。

| 方向 | 消息 `type` | 载荷 |
|---|---|---|
| 宿主 → 插件 | `hello` | `protocolMajor`、`pluginId`、`version` |
| 插件 → 宿主 | `ready` | 同一版本信息、`methods`、`events`，与签名清单一致 |
| 宿主 → 插件 | `call` | `id`、`method`、`params`、`owner`、`timeoutMs` |
| 插件 → 宿主 | `result` | `id`、`value` 或 `error: {code,message}`，二者必选其一 |
| 宿主 → 插件 | `cancel` / `releaseOwner` | 分别传 `id` / `owner` |
| 插件 → 宿主 | `event` | `owner`、`event`、`payload` |
| 宿主 → 插件 | `shutdown` | 无附加字段，工作进程释放资源后退出 |

插件收到 `cancel` 后，在同一请求 ID 的 `result.error` 中返回 `code: "ABORTED"`，表示已停止该请求并完成资源收尾。宿主等待最多 300 毫秒。确认后复用进程，逾期或响应不合规时回收实例。应用侧仍按发起方收到超时或取消结果。

`owner` 是宿主分配的会话标识，网页不能提供。应用通过 `plugin.call` 传递独立的 `pluginId`、`method` 和 JSON `params`，逻辑方法名为 `plugin.<pluginId>.<method>`。宿主校验依赖及授权后按插件 ID 解析绑定实例。参数 JSON 上限为 240 KiB，为 IPC 帧信封保留空间。握手与关闭各限 5 秒，普通调用默认 5 秒且最多 30 秒。撤销会话时取消请求并发送 `releaseOwner`，宿主立即撤销句柄与订阅。恶意或不合规帧关闭该实例，受影响的在途调用返回 `PLUGIN_UNAVAILABLE`。

## 窗口与配置

- 主窗口按应用 ID 唯一。启动中合并重复请求，运行中聚焦已有窗口，关闭协商被拒绝时回到运行状态。窗口真正销毁后才允许新建。
- 窗口大小按逻辑像素记录，恢复时检查显示器与工作区。配置按平台、应用、插件作用域存放，普通应用仅访问自身授权范围，插件配置由宿主代管。
- SQLite 事务处理配置写入和迁移。升级前备份，失败回滚事务并记录原因。凭据使用 Windows 保护存储，配置库保存引用。应用更新保留配置，卸载按用户选择处理数据。

## 样例验收

| 样例 | 场景 |
|---|---|
| 便签 | 新格式包安装与更新、窗口聚焦、分块文件保存、取消关闭、重启恢复 |
| 请求台 | 签名安装、端点授权和撤销、HTTP、受信 TLS、证书拒绝、重定向、取消、超限和分块响应 |
| 设备控制 | 插件缺失及版本冲突、打开和读写、拔插、竞争占用、权限撤销、插件崩溃和升级失败恢复 |

首个硬件样例选用串口，真机验收使用可拔插 USB 串口与独立回显设备或 TX/RX 回环，测试模式为 115200、8N1。实际型号、驱动版本和测试机器在 M5 验收报告中记录。

配置首版库版本为 1，键由 `scope + ownerId + key` 唯一确定，值为 JSON。平台作用域使用固定宿主所有者，应用与插件作用域分别使用已验证 ID。数据库版本高于运行时支持值时拒绝写入。窗口位置和大小由宿主保存到应用作用域的保留键。

按契约复估，M2–M8 仍采用 50–80 人日区间。打包与应用管理 10–16 人日，通信、配置和窗口 12–18 人日，插件进程和串口 13–22 人日，界面、验收和交付 15–24 人日。M2 的打包容量和 M4 的进程权限原型测量后更新估算。
- 应用清单可选 `icon`，为 96×96 静态 WebP 的 Base64 字符串，最多 16384 个 ASCII 字符。打包工作台会将上传图片裁切并编码为此格式。图标随清单签名，安装后由桌面显示，省略时使用通用图标。插件清单无此字段。
