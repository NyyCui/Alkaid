## 2026-11-05 M7 二进制分块复制优化

- 旧 SDK 每个 64 KiB 读块在校验和交付时各解码一次，写块又逐字节拼接 Base64 编码前的字符串。32 MiB 复制累计 512 次读块与 512 次写块，转换产生大量短命对象。宿主仍在提交时刷盘。
- 读块只解码一次，校验后直接复用字节数组。支持时用 Chromium 的 Uint8Array Base64 接口，其余环境使用有界分组转换。原有块大小、顺序背压、规范 Base64 校验及取消／提交语义保留。
- 同机、同 32 MiB 真实 CEF 逐字节复制从 16,588 ms 降到 3,745 ms（约 77%）。复制前后的 JS 堆从 0.78→35.50 MiB 变为 0.78→5.00 MiB。采样不代表峰值或进程总内存。新报告位于 `build/stream-ui-verification/run-1793843525688/evidence/transfer-baseline.json`。

### 容量含义

| 层次 | 当前行为 |
|---|---|
| 传输块 | 64 KiB 是一次原始字节块大小，不是文件上限 |
| 外部文件 | 分块读取无原 128 KiB 限制；每应用活跃写入的暂存合计上限 8 GiB |
| 私有文件 | 单份最多 64 MiB，每应用 128 份、内容合计 128 MiB |

### CEF 适配层必须满足的接入条件

1. 创建浏览器时由宿主选择应用并调用 bindBrowser，禁止从页面 JSON 接受应用角色、appId 或来源。
2. 导航开始立即 invalidateDocument 并 discardSession。新主文档通过 CEF URL 解析取得规范 scheme/host 后才 openDocument；不以不可信 Renderer 消息充当已验证导航事件。
3. 每次消息接收从实际 CEF browser/frame 构造 DocumentIdentity；sessionId 由适配层映射，并随桥接上下文切换。当前核心中的 sessionId 是宿主内部代次，不是可公开复用的认证秘密。
4. 在 JSON 解码前计算真实 UTF-8 报文长度，再做信封和方法参数校验；CallRequest.payloadBytes 由适配层填写，不能采信页面字段。当前核心不包含 JSON 解码器，SDK 检查不能替代宿主参数验证。
5. 实际处理器注册完成后才 enableMethod。begin 通过后排队，执行前 checkReady；系统操作完成回到宿主线程 finish，失败不得发送成功结果。
6. 核心注册表与网关均由同一宿主线程拥有，不可在工作线程直接访问。权限撤销与系统操作之间的资源控制需要服务层协作；finish 拒绝结果不能撤销已发生的文件写入等副作用。
7. 宿主定时调用 expire 并回复仍有效文档的超时；超时不代表系统操作已取消，写操作不能自动重试。
8. 生命周期回调执行清理，避免仅依赖前端 dispose。限制浏览器/会话总量；本批已实现每会话请求限额，总体资源预算留在宿主接入阶段实施。
