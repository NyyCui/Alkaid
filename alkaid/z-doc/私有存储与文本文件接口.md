# 私有存储与文件接口

对应 `2.0.0-dev.5`，协议版本仍为 1。便签的编辑、字号、草稿和保存交互均在 `samples/notes/` 的前端实现；C++ 只提供通用存储、文件选择、字节流和编码转换能力。

## 授权与隔离

安装包可声明四种权限：`storage.kv`、`files.private`、`files.userSelected.read`、`files.userSelected.write`。未知和重复权限拒绝安装。受信桌面的安装预览展示全部权限，并标出本次新增授权；已信任发布者的更新也必须再次确认。

注册表从 v1 增量迁移到 v2，增加 `apps.grants`，原有应用、发布者、任务记录保留。旧版空权限应用迁移为 `[]`。授权和版本激活在同一事务提交。实际可调用能力是清单声明、平台白名单、已确认授权三者的交集。

显式回退不能恢复当前已收缩的权限，遇到这种情况返回 `PERMISSION_DENIED`。损坏包自动恢复到上一版本时仍保留当前授权上限，因此旧版声明更多权限也不能获得额外能力。卸载后数据保留，重新安装仍受原发布者绑定和权限确认约束。

宿主从真实 browser/frame/document 确定应用身份，应用无法指定另一个应用的数据目录。普通应用无权管理其他应用；桌面管理角色也不自动获得应用私有存储权限。

## SDK

```js
const stored = await client.storage.get('preferences');
const fontSize = stored.found ? stored.value.fontSize : 19;
await client.storage.set('preferences', { fontSize: 23 });
await client.storage.batch([
  { type: 'set', key: 'preferences', value: { fontSize: 19 } },
  { type: 'remove', key: 'old-setting' },
]);

await client.files.writePrivateText('draft.txt', '仅此应用可读的草稿');
const draft = await client.files.readPrivateText('draft.txt');

const opened = await client.dialog.openFile();
if (opened) {
  const text = await client.files.readText(opened.handle);
  await client.files.close(opened.handle);
}

const target = await client.dialog.saveFile();
if (target) {
  await client.files.writeText(target.handle, '要保存的 UTF-8 文本');
  await client.files.close(target.handle);
}
```

下面为兼容旧 SDK 的直接 RPC。新版 SDK 的同名文本方法使用下方分块 RPC，不受旧单次文本报文的 128 KiB 限制。

| 接口 | RPC 参数 | 返回 | 权限 |
|---|---|---|---|
| `storage.get(key)` | `{key}` | `{found, value}`；JSON null 与不存在可区分 | `storage.kv` |
| `storage.set(key, value)` | `{key,value}` | `null`，事务提交完成 | `storage.kv` |
| `storage.remove(key)` | `{key}` | `null`，不存在也成功 | `storage.kv` |
| `storage.batch(operations)` | `{operations}` | `null`，全部提交或全部撤销 | `storage.kv` |
| `files.readPrivateText(name)` | `{name}` | 文本；不存在为 `null` | `files.private` |
| `files.writePrivateText(name,text)` | `{name,text}` | `null`，事务提交完成 | `files.private` |
| `files.removePrivate(name)` | `{name}` | `null`，不存在也成功 | `files.private` |
| `dialog.openFile()` | `{}` | 只读 `FileGrant`；用户取消为 `null` | `files.userSelected.read` |
| `dialog.saveFile()` | `{}` | 可写 `FileGrant`；用户取消为 `null` | `files.userSelected.write` |
| `files.readText(handle)` | `{handle}` | UTF-8 文本 | `files.userSelected.read` + 当前会话句柄 |
| `files.writeText(handle,text)` | `{handle,text}` | `null`，内容写入完成 | `files.userSelected.write` + 可写句柄 |
| `files.close(handle)` | `{handle}` | `null`，释放句柄 | 只允许关闭当前会话持有的句柄 |

`FileGrant` 仅包含 `{handle, name, writable}`，不包含路径。句柄是宿主生成的 256 位随机标识，绑定当前应用的当前文档；刷新、导航、关闭、卸载后不能继续使用，重启也不恢复。`files.close` 不要求额外权限，但不能凭它取得文件访问权。

打开对话框只授予读取。要覆盖该文件，仍须通过保存对话框选择并确认目标，原有只读句柄不会被升级。对话框标题由宿主提供并带应用名称，已有目标使用 Windows 覆盖确认。保存选择本身不创建或截断文件，只有写入事务提交后才替换目标。

## 私有数据与限额

宿主保存于 `data/private/<宿主分配的origin>/content.sqlite`，使用独立 SQLite WAL/FULL 数据库，与安装注册表、浏览器 profile 分离。私有文本是数据库内的命名文本对象，并非向网页暴露可遍历的本机文件系统。应用不获得数据库连接或 SQL 执行接口。

| 项目 | 当前限制 |
|---|---|
| KV 键或私有文本名称 | 1～80 个 ASCII 字母、数字、`_ - .`，排除设备名、路径、尾部点 |
| 单个 KV 值 | JSON 编码后最多 64 KiB |
| KV 总量 | 每应用 128 个键、1 MiB；计入键名和 JSON 值字节 |
| 批处理 | 1～64 个 set/remove；按最终状态检查配额，失败整批回滚 |
| 私有文件 | 分块单份最多 64 MiB；每应用 128 份、内容总计 128 MiB（旧文本 RPC 计入名称） |
| 外部文件 | 分块读取没有 128 KiB 文件上限；每应用同时暂存写入合计最多 8 GiB |
| 传输块 | 原始读取/二进制块最多 64 KiB；文本写入块最多 64 KiB UTF-8 输入；编码转换后的字节数可能不同 |
| 活跃流 | 每应用最多 8 个，其中写入最多 4 个；5 分钟无活动自动释放 |
| SDK 整文件读取 | 默认源字节及解码 UTF-8 预算 16 MiB，maxBytes 可设 0～64 MiB；逐块接口没有此整文件预算 |
| 便签正文 | 最多 8 MiB UTF-8；这是 textarea 应用的编辑容量，不是平台文件上限 |
| 兼容旧文本 RPC | files.readText/writeText/readPrivateText/writePrivateText 单次仍为 128 KiB，仅 UTF-8 |
| 文件句柄 | 每应用最多 16 个，使用后主动 close |
| 数据服务请求 | 每应用最多 16 个在途请求，串行后台执行 |

普通调用最多 15 秒；SDK 文件选择等待最多 5 分钟。取消、超时、会话失效会释放待处理请求，后台在执行前、提交前检查请求有效性，回 UI 线程后再次检查网关许可。迟到的选择结果不会创建可供新页面使用的授权，已生成但未投递的句柄会关闭。对话框超时后用户仍可能需要手动关闭 Windows 选择窗口。

超过文本/参数限制返回 `INVALID_REQUEST` 或 `FILE_TOO_LARGE`，超出累计数据配额返回 `QUOTA_EXCEEDED`。其他常见错误：`PERMISSION_DENIED`、`HANDLE_EXPIRED`、`FILE_ENCODING`、`FILE_BUSY`、`FILE_CHANGED`、`TIMEOUT`。失败不伪装成功。

## 分块协议

新版 SDK 自动封装以下 RPC。应用通常使用 `files.readText/writeText/readBytes/writeBytes/readChunks/writeChunks/readTextChunks`；私有文本使用 `readPrivateText/writePrivateText`。底层私有流也接受 binary，但目前 SDK 的私有便捷接口只封装文本。每块顺序等待响应提供背压，避免把整个文件塞入一条 IPC。

| RPC | 参数 | 返回/含义 |
|---|---|---|
| `files.beginRead / beginWrite` | `{handle,encoding}` | `{streamId,totalBytes,encoding}`，需要对应读/写权限和当前会话句柄 |
| `files.beginPrivateRead / beginPrivateWrite` | `{name,encoding}` | 同上，私有读取不存在返回 null；需要 files.private |
| `files.readNext` | `{streamId}` | `{text或data,processedBytes,totalBytes,eof,encoding}`；data 为严格 Base64 |
| `files.appendChunk` | `{streamId,index,text或data}` | `{index,writtenBytes}`，index 从 0 顺序递增，返回下一 index；writtenBytes 是已暂存的编码后大小 |
| `files.commitWrite` | `{streamId}` | null，完成实际提交并释放流 |
| `files.abortStream` | `{streamId}` | null，释放当前流并清理未提交暂存 |

streamId 为随机 256 位标识，绑定创建者的应用与文档。后四个方法虽不重复要求文件权限，但必须持有本会话已授权的流；其他应用、旧页面及猜测标识不能使用。读取 EOF、操作失败、主动取消、关闭关联文件句柄或会话撤销都释放流；重复使用返回 STREAM_EXPIRED。流生命周期的 5 分钟空闲期限与单次 RPC 的 15 秒期限不同。

写入在临时文件暂存，尚未 commit 不影响原文件。单个文件句柄/私有名称只允许一个活跃写事务；错序块返回 STREAM_SEQUENCE 并销毁该事务。外部文件按选定快照提交；私有对象以 revision 校验并在 SQLite 事务中通过增量 BLOB API 读写，既避免整份大草稿驻留宿主内存，也防止覆盖同时更新的对象。旧私有数据库以 ALTER TABLE 添加 revision，已有草稿与设置保留。读取过程中私有对象变化返回 FILE_CHANGED，调用方须重新读取。

传输取消通过 AbortSignal 在块间和提交前生效，失败时 SDK 尝试 abort。宿主还在执行和提交前检查会话许可。取消不能撤销已经提交的内容；超时/断线后的写操作不得盲目自动重试。私有目录内仅清理平台命名的过期暂存；用户目录里的进程中断恢复文件不自动删除。

## 文本编码

- 读取编码：auto、utf-8、utf-8-bom、utf-16le、utf-16be、gb18030；写入不接受 auto。binary 不解码，保留包括 NUL 在内的所有字节。
- auto 识别 UTF-8 BOM 与 UTF-16 LE/BE BOM；没有 BOM 按 UTF-8。GB18030 必须显式选择，不做不可靠的编码猜测。UTF-32 BOM 暂不支持。
- 宿主跨块保留不完整字符；严格拒绝无效序列和文本 NUL，不用替换字符掩盖乱码。GB18030 采用 Windows CP54936 转换，实际字符映射跟随系统实现。
- 文本读取剥离对应 BOM。utf-8 写入无 BOM，utf-8-bom 写入 BOM，utf-16le/be 写入对应 BOM；空文本也遵循该规则。二进制空文件保持零字节。
- 整文件 SDK 的 maxBytes 同时约束源大小与解码后 UTF-8 大小；文本转为 JS 字符串、拼接等会有额外内存开销。更大数据请逐块消费，避免累计全部块。

## 文件保存与限制

只接受本地固定磁盘的普通文件；拒绝 UNC、设备路径、目录、备用流、重解析点、目录链接和多硬链接文件。逐级持有目录句柄，读取选定文件句柄而不是由网页拼接路径。持有文件时不共享写访问；保存前核对文件身份、大小和最后修改时间快照，发现替换或变化要求重新选择。

写入先在选定目录创建随机暂存文件，完整写入并 `FlushFileBuffers` 后再提交。已有文件使用带备份的 `ReplaceFileW` 保留原访问控制等元数据；新文件用不允许覆盖的同目录移动提交。正常完成后清理备份。特殊替换中断返回 `FILE_RECOVERY_REQUIRED` 并保留同目录 `.alkaid-transfer-<id>.bak/.tmp`（旧 RPC 为 `.alkaid-<id>.bak/.tmp`），错误信息指出恢复文件命名范围；进程突然退出也可能留下这些文件，不自动删除用户目录里的恢复资料。实现依据见 [Windows ReplaceFileW 文档](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)。

这保证正常失败不会先截空原文件，但不是文件系统级 compare-and-swap，也不承诺抵御另一个本机进程在检查与提交之间恶意替换同名文件。取消和超时不能撤销已经提交的写入。尚未验证断电、磁盘满、特殊 ACL、杀毒软件干预和所有文件系统组合。

当前没有目录授权、目录枚举和永久路径收藏。二进制接口可读写图片、PDF 等原始字节，但本阶段没有新增图片/PDF 预览器。便签使用 textarea，保存文本遵循其换行归一化行为；文件编码转换在宿主完成。私有数据按应用隔离，但未加密，不是对本机账户管理员的保密边界。

## 体验与验证

启动 `build/host/run/alkaid_host.exe`，从桌面安装 `build/examples/notes-1.1.0.ypkg`。发布者指纹见同目录 `publisher-fingerprint.txt`。示例支持新建、打开、编辑、保存、另存为、Ctrl+S、字号设置和私有草稿恢复。

草稿状态显示成功才表示已提交。新版便签登记关闭处理器：先等待最后一笔草稿和字号设置提交，再提供保存到文件、保留草稿或返回编辑三项选择。保存失败保留窗口。平台只有在全部应用同意后才关闭窗口；有应用拒绝或 30 秒不响应则取消退出，恢复已经同意应用的交互。旧包未登记处理器时仍直接关闭。CEF 已开始销毁的强制浏览器关闭、直接 window.close 和结束进程不属于可取消的保存协商路径。完整 SDK 用法见 [关闭前保存](../packages/sdk/README.md#关闭前保存)。

```powershell
ctest --test-dir build/host -C Release --output-on-failure
node --test packages/sdk/test/client.test.ts packages/sdk/test/streams.test.ts tests/desktop/bridge.test.mjs
node scripts/test-packages.mjs
node scripts/test-data-permissions.mjs
./scripts/verify-data-ui.ps1 -NodePath <node.exe路径>
node scripts/prepare-stream-tests.mjs
# 验证实际交付包而非候选包：
$env:ALKAID_TEST_NOTES_PACKAGE=(Resolve-Path build/examples/notes-1.1.0.ypkg).Path
./scripts/verify-stream-ui.ps1 -NodePath <node.exe路径>
```

Windows 文件测试需要正常宿主权限；受限执行沙箱可能拒绝测试用的硬链接或重命名。全部测试使用 `build/` 内独立数据和测试文件，不向默认运行数据目录安装测试应用。原生交互测试仅针对指定测试宿主 PID；验证记录与截图位于 `build/data-ui-verification/` 和 `build/stream-ui-verification/`。
